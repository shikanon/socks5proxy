# 项目内服务组网（实验能力）

## 定位与性能结论

本模块是对现有能力的可选增量，不使用Tailscale、Headscale或tsnet，不替换现有代理、PAC、域名策略、登录启动或TCP入口。自主实现节点目录、服务地址映射、租约注册/发现、权限判断和节点间QUIC流调度；TLS和QUIC使用Go标准库与项目既有quic-go依赖，不自行实现加密算法。

当前裁决为 **EVIDENCE_REQUIRED：没有证明比生产random TCP＋BBR更快**。组网组织方式不是带宽优化算法。固定出口、公网线路不变时，注册/发现不能减少物理RTT；长驻QUIC会话和多流可能减少每次新建远端TCP的开销，但UDP丢包、流控、CPU、封装、出口连接和中继都会影响结果。当前新增能力没有NAT打洞或中继，不代表已解决UDP受限线路。

源码测试只证明本地隔离功能，不证明实际海外线路、完整客户端或Codex可用。Linux内核BBR不作用于QUIC UDP拥塞控制；外网目标的TCP连接仍由原服务端建立。旧全IP QUIC DATAGRAM模式和新增服务流模式是不同路径，不能混用旧测试结果宣称本版提速。

## 已实现范围

- 每个节点有证书SAN身份、固定虚拟IPv4、授权实际UDP端点和可导出虚拟端口。
- 虚拟地址来自100.64.0.0/10，但只是本模块的服务地址，不写入OS网卡；不应与其他VPN地址映射混用。
- 独立HTTPS mTLS目录支持 `/v1/register` 和 `/v1/peers`。只接受已配置节点和预先授权端点；租约90秒、节点循环30秒更新。目录重启后动态租约为空，节点重新注册。身份、IP、端点授权来自静态配置，**不是自动分配地址或自由自注册系统**。
- 控制服务不承载网站数据。对等节点直连QUIC；每个目标复用连接，新应用会话使用独立可靠双向流。每端点握手8秒，服务协商8秒，流空闲300秒，128条导出活动流，128个已接收连接，禁止0-RTT。
- 服务协商发送1字节版本与2字节虚拟端口，接受方返回1字节状态后才允许调用方发送业务数据。服务不指定任意目标，只映射到配置中的回环TCP地址。
- mTLS验证CA与节点SAN；出口ACL允许列表决定哪些节点能访问哪个虚拟服务。未授权、未知地址、端口、过期发现租约或服务失败不会自动转公网直连。
- `ProxyOptions.UpstreamDialContext`仅替换客户端连接远端代理的那一跳。规则直连仍使用原直连拨号，服务端连接公网目标也不调用该钩子。
- 节点配置进行深拷贝，运行时ACL不别名引用调用方；显式关闭取消组网连接，半关闭保留反向流。

没有实现：系统TUN、IP包转发、UDP应用转发、自动NAT打洞、STUN、DERP等中继、自动路径最优、透明多跳、证书签发平台、证书热轮换/撤销、管理Web UI、多租户及生产自动部署。因此本版是**可运行的服务组网基础版**，不是完整Tailscale重实现，也不是生产网络替换。

## 文件与控制命令

```bash
go build -o dist/mesh ./cmd/mesh
./dist/mesh check -config PRIVATE_CONFIG
./dist/mesh control -config PRIVATE_CONTROL_CONFIG -control-listen 127.0.0.1:18443
./dist/mesh node -config PRIVATE_NODE_CONFIG
./dist/mesh peers -config PRIVATE_NODE_CONFIG
./dist/mesh proxy -config PRIVATE_CLIENT_CONFIG \
  -local 127.0.0.1:18898 -server 100.64.0.2:8080 \
  -secret-file PRIVATE_PROXY_SECRET
```

PRIVATE_*是需由部署者提供的文件参数，不是仓库附带凭据。控制监听默认回环，需要其他主机访问时应明确指定地址并独立授权网络入口；不能照搬旧公网TCP来源规则到组网接口。

默认独立HTTP入口18898避免覆盖生产8888。服务端node把虚拟8080映射到回环28888上已经运行的本项目random应用服务，客户端保留原SOCKS协商和混淆协议，外层QUIC提供加密与节点认证。没有秘密文件或CA时拒绝启动，不降级到不验证的TLS。

`examples/mesh/{client,server,control}.example.json`是文档地址配置，不能实际联网。可通过以下命令在一个已经存在的新目录生成示例，已有文件会拒绝覆盖：

```bash
./dist/mesh examples -examples-dir NEW_EXISTING_DIRECTORY
```

三个节点证书须由同一可信CA签发：DNS SAN恰好只有本节点ID，并具备客户端/服务端TLS用途。CA私钥不分发到节点；证书和密钥路径默认示例为private目录，本项目不代签发生产凭据。配置路径相对于进程工作目录，建议实际部署使用绝对私有路径。私钥权限0600，私人证书配置与诊断不能提交Git。

控制地址必须是无凭据、无path/query的HTTPS origin；不跟随重定向，控制连接不继承HTTP_PROXY。这避免启动依赖尚未启动的本项目代理。控制域名/公网地址与证书身份的绑定由 `control_name` 指定。

## 与现有域名分流关系

现有 `proxy-service`仍运行原生产通道，不会因构建mesh自动启用组网。通过可选上游接口已验证“HTTP入口→组网虚拟服务→原random代理→测试目标”链路。

如需接入现有多组管理器，需要为每个出口准备独立mesh HTTP后端，再使组入口指向对应本机端口，并复用原组探针；本轮**没有修改生产适配器或启用组网后端调度**。普通组/特殊组默认、手动偏好、现有TLS连接不随优先级迁移的契约应保留。

组网进程不安装系统路由、DNS、防火墙或自启项，独立豆包工作不会因它被透明接管。忽略HTTP代理的其他程序也不会自动进入本组网；这不等于“按进程强制拦截”。

## 安全与运行边界

- CA证书授权身份；地址段不是身份认证。允许节点能调用的服务必须最小化，不能开启Funnel或公网无认证服务。
- 本模块导出目标只允许字面回环地址。导出的应用代理自身可能允许任意公网/内网目的；出口目标权限需由应用服务或独立网关限制，不可把组网ACL当作完整SSRF防护。
- 配置白名单是可信本地管理数据；目录不能增加名单之外的节点、IP、端点或服务端口。主动更新陌生端点必须先更新授权配置。
- 发现租约过期拒绝新Dial；已有流不因目录暂时失联主动重放或迁移，但节点/证书/网络失败仍可能断开。
- 证书过期、轮换、配置变更需受控重启并保留旧配置；长连接不保证零中断。
- 新版不更改原依赖版本。增加模块必须构建与测试后发布，单纯git拉取不能让现有运行二进制获得组网能力。

## 最小性能实验合同（尚未执行）

- 基线：生产同版本random TCP＋BBR；候选：同原应用协议＋新增QUIC服务通道。比较只改变入口到同一出口的传输，其余出口、目标、样本、响应体、并发、TLS、区域策略与设备保持一致；这属于功能组合通道对比，不归因于“组网控制目录”提速。
- workload：冷启动/已复用连接、HTTPS短响应、固定大小上下行、1与8并发、双向长连接；健康/失败、UDP可达/受限、节点恢复独立分组，不能合并平均。
- 冻结revision、源文件hash、Go/runtime、配置与随机种子，先刻画原代理语义，再验证候选保持字节一致、DIRECT例外、半关闭、取消、失败不重放。故意破坏这些语义的测试替身必须触发测试失败。
- 交替AB/BA配对，保留每对原始首响应、吞吐、失败率、CPU/RSS、实际路径、时间与网络环境；关闭诊断后测量，不用单次最优数据。
- 改善/允许回归门槛需采样前根据业务要求确定。缺少门槛或原始配对结果时裁决EVIDENCE_REQUIRED，不填猜测提升百分比。指纹漂移或语义失败即REMEASURE/REJECT，不启动生产切换。

本轮没有测跨境带宽，没有启用远端组网服务、改变Mac代理、修改原服务器配置或提交到GitHub。
